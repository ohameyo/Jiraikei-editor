# 图层元素体验调教

## 优先级
P0，本窗口专门推进。

## 范围
只处理画布图层元素体验：腮红、贴纸、马赛克、文字元素在画布上的点选、移动、缩放、旋转、复制、删除、控制器展开、释放后显示、移动中实时预览和移动端触控体验。

本任务不处理滤镜、导出、整体布局。

## 背景
当前最高优先级是移动端滑杆和元素操作丝滑度优化。滑杆和部分元素拖动已经做过一轮性能处理，但图层元素体验仍分散在多个任务中：点选后控制器展开、手动腮红选区、马赛克/贴纸比例与移动预览、释放后图案显示等需要在同一条体验链路里继续打磨。

目标是让画布元素像原生修图 App 一样可靠：手指点得到、拖得动、缩放旋转跟手，松开后立即稳定落位，控制器只在需要时出现。

## 当前问题
- 点选贴纸、文字、马赛克、腮红选区后，对应控制器必须立即展开。
- 添加新元素后，应自动选中并展开对应控制器。
- 点击空白处应取消选中并收起元素控制区。
- 未选中元素时，移动端元素控制区不应遮挡功能区。
- 移动、缩放、旋转时，元素内容和选框需要同步跟手，而不是只有选框移动。
- 释放元素后，图案必须立刻留在当前位置，不能只剩选框或等点击空白后才恢复。
- 复制、删除入口需要在选中元素时清晰可用，并和 PC/移动端控制器状态一致。
- 手动腮红选区需要容易点选、移动、缩放，切换 tab、点原图、恢复原图后不应复位。
- 腮红选框过小时，控制按钮不应盖住选框；按钮视觉尺寸应固定，触控热区单独扩大。
- 未识别人脸进入手动腮红时，左右腮红默认距离需要更远，便于手指分别拖拽。
- 贴纸、文字、马赛克等其他图层元素在移动端也需要最小可操作选框，避免小元素控制点挤在一起。
- PC 端不应在画面左上角显示空内容、非法尺寸或不可见图层的选框。
- 移动端腮红左右选区即使实际位置很近，控制按钮也不能堆叠到无法点选；交互层不应强行改动用户确认的腮红位置。
- 爱心马赛克移动、缩放时应显示心形预览。
- 爱心马赛克移动端 overlay SVG 预览必须和实际 canvas 马赛克遮罩心形完全一致。
- 贴纸和马赛克不应因图片比例变化而变形。
- 移动端触控需要兼顾命中区域、pointer capture、滚动冲突和 Safari/内嵌浏览器差异。
- 移动端贴纸、文字、马赛克等图层元素需要支持双指缩放手势。
- 移动端点选画布上的贴纸、文字、马赛克时，需要立即切换到对应 tab 并弹出当前图层控制器。
- 移动端双指缩放不能要求第二根手指必须精确落在小元素选框内；第二根手指落在画布内也应参与当前图层 pinch。
- PC 端清空画布后编辑第二张图时，腮红编辑态、预览态和上一张图的手动腮红坐标不能残留，避免无法重新编辑腮红选框。
- 删除腮红选区必须可彻底删除；删除最后一个腮红选区后不应自动重新生成左右两个默认腮红。

## 已做修改
- 滑杆改为通过 pointer 位置主动计算数值。
- `input[type="range"]` 使用 `touch-action: none`。
- 移动端滑杆提交与轻量预览重绘降频，减少滤镜重算挤占主线程。
- 拖动元素时用 overlay preview 跟手，并通过 `activeTransformLayerId` 隐藏 canvas 内原元素。
- 图层移动/缩放/旋转首帧先更新 DOM overlay preview，把隐藏 canvas 原图层的重绘推到下一帧。
- 移动端 range thumb 和轨道加大，提升手指命中和拖动稳定性。
- 元素控制区改为选中图层后展开。
- 图层集合按钮放在画布右上。
- 识别失败时会进入手动腮红 fallback。
- 腮红选区加大过，便于手指操作。
- 原图滤镜会保留手动腮红区域。
- 爱心马赛克拖动预览改为 SVG 心形。
- 马赛克贴纸比例问题做过修复。
- 移除误加的医疗贴纸。
- 记录自动腮红是否真实识别成功，识别失败时不再沿用启发式人脸框作为手动腮红默认位置。
- 未识别人脸的手动腮红默认位置改为左右更分开，默认选区略放大，便于直接点选和移动。
- 移动端图层与腮红 overlay 增加最小可操作选框，实际预览仍按真实元素尺寸居中显示。
- 选框控制按钮视觉尺寸固定为较小圆点，使用透明伪元素扩大触控热区，避免按钮盖住小选框。
- 缩放元素时给控制按钮加反向缩放变量，避免按钮跟随选框缩放而忽大忽小。
- 爱心马赛克的 canvas 遮罩和 overlay SVG 预览改为复用同一组心形路径控制点，避免预览形状和实际马赛克形状不贴合。
- Overlay 渲染过滤空文本、缺失贴纸资源、透明或尺寸非法的图层，避免 PC 端出现空元素选框。
- Overlay 渲染增加可见面积判断，过滤中心落在左上角、主体基本在画布外的图层控制框。
- 移除手动腮红编辑态的左右最小间距强制避让，保留用户拖出的真实腮红位置。
- 腮红控制按钮改为符合缩放逻辑的对角分布：删除在右上，缩放在左下，减少移动端按钮堆叠。
- 腮红左下缩放按钮的 hover 光标改为 `nesw-resize`，和左下到右上的缩放方向一致。
- 撤回左右腮红颜色与文字标签区分，避免额外视觉干扰。
- 右腮红缩放按钮放在右下角并使用 `nwse-resize`，对应左上右下方向；左腮红缩放按钮保留左下角并使用 `nesw-resize`。
- 控制按钮视觉尺寸进一步固定为 20px，保留透明触控热区，降低遮挡。
- 图层元素移动交互增加多指 pointer 跟踪；第二根手指按住同一图层时进入双指缩放，按两指中心移动图层、按两指距离缩放图层。
- 双指缩放时贴纸保持比例，文字同步调整字号，马赛克同步调整宽高。
- 移动端画布元素 `pointerdown` 选中时同步调用控制器展开逻辑，确保点选或拖动开始时都会切换到对应 tab 并打开图层控制器。
- `setActiveTool()` 统一补齐贴纸、文字面板的懒加载，避免从画布点选切 tab 后面板内容未初始化。
- 双指缩放补充画布级 `pointerdown` 接入，第二根手指落在元素外但仍在画布内时也会加入当前图层 pinch。
- 图层多指交互释放逻辑改为等所有 active pointers 结束后再提交，避免第一根手指抬起就提前取消缩放状态。
- 清空画布、恢复原图、导入新图时显式结束 overlay 交互并重置腮红编辑/预览 UI 状态。
- 导入新图时 `resetFiltersToOriginal()` 不再保留上一张图的手动腮红区域，避免第二张图沿用旧坐标导致选框不可编辑。
- 手动腮红初始化尊重 `blushManual` 状态：已进入手动编辑后，即使所有腮红选区都被删除，也不自动生成新的左右选区。
- 第二组腮红删除逻辑改为只在第二组左右都关闭时才关闭整组，避免删除一侧误隐藏另一侧。

## 验收标准
- 点击画布上的贴纸、文字、马赛克、腮红选区，立即选中并展开对应控制器。
- 添加新元素后，自动选中并展开对应控制器。
- 点击空白处可取消选中并收起元素控制区。
- 移动、缩放、旋转贴纸/文字/马赛克/腮红选区时，元素内容和选框同步跟手。
- 松手后元素立即在当前位置显示。
- 复制、删除入口在 PC 和移动端都能对当前选中元素生效。
- 未选中元素时，移动端元素控制区不遮挡功能 tab。
- 手动腮红选区可轻松点选、移动、缩放，切换 tab、点原图、恢复原图不改变已确认位置。
- PC 端不会在画布左上角出现没有内容的图层选框。
- 主体基本不在画布内的图层不会显示孤立控制框。
- 移动端两个腮红选区可以按真实需要靠近，按钮不重叠且仍可点选。
- 腮红缩放按钮的摆放和 hover 光标方向一致。
- 移动端双指捏合贴纸、文字、马赛克时，元素能跟随两指中心移动并实时缩放。
- 移动端第二根手指落在当前元素附近的画布区域时，仍可触发当前选中图层双指缩放。
- 移动端点选贴纸、文字、马赛克时，底部 tab 自动切到对应功能，图层控制器立即展开。
- PC 端完成一张图后清空画布并导入第二张图，点击编辑腮红选区能正常显示、拖动、缩放腮红选框。
- 删除第一个腮红选区后继续删除第二个，画布上保持空腮红状态，不会自动恢复两个腮红选区。
- 爱心马赛克拖动、缩放时显示心形预览。
- 爱心马赛克预览心形和释放后的实际马赛克心形边缘、尖角、凹口一致。
- 贴纸和马赛克不会因图片比例变化而变形。
- 小尺寸图层元素在移动端仍能点选、拖动、缩放、复制、删除，控制点不互相遮挡。
- PC 端元素操作不退化。

## 遗留风险
- 移动端 Safari/内嵌浏览器对 pointer capture、range 控件和 `touch-action` 行为差异较大，需要实机反复验证。
- 图层拖动开始的极短瞬间可能仍会同时看到 canvas 旧位置和 overlay preview，需在真机上确认观感是否可接受。
- 控制器展开、active layer、active tool 三者状态如果继续分散，后续新增元素类型时容易回归。
- 最小可操作选框会让极小元素的选中框大于真实视觉内容，需在真机上继续确认是否符合预期。
