# 移动端画布与功能区布局整理

## 优先级
P1。

## 背景
移动端需要类似修图 App：画布占比高，功能区简洁，子功能按需出现。

## 当前问题
- 子功能 tab 和参数区容易挤压画布。
- 某些功能区内容为空时可能露出不一致色块。
- 贴纸、预设、胶囊按钮需要保持小巧精致。
- 移动端清空画布后再次点击画布空态上传下一张照片，文件选择器必须稳定弹出。
- 移动端确认腮红后再清空画布，腮红 overlay 不能残留在空画布上拦截下一次上传点击。
- PC 端缩小窗口时不应连续缩放或过早切到移动端布局；只有窗口达到手机纵向比例时才允许进入移动端布局。手机和平板无论窗口尺寸如何都应保持移动端布局。

## 相关文件
- `index.html`
- `styles.css`
- `src/app.js`

## 已做修改
- 移动端画布固定。
- 功能 tab 高度缩小。
- 预设胶囊和贴纸排列做过压缩。
- 去掉移动端重复上传 tab。
- 画布空态上传改为每次创建一次性 file input，避免移动端复用隐藏 input 导致清空后第二次上传失败。
- 无图片时强制隐藏 overlay layer，并在清空画布时清空 overlay DOM，避免确认腮红后的控制层残留挡住空态上传。
- 画布空态增加层级，确保空态上传入口高于历史 overlay/processing 层。
- 空画布区域增加真实 file input 覆盖层，移动端点击空画布时直接触发系统相册，不再依赖 JS 程序点击隐藏 input。
- JS 布局判断改为设备类型 + 手机比例窗口：手机/平板 UA、iPad 桌面 UA 进入移动布局；PC 窄窗口只有在宽度不超过 760px 且高宽比达到 1.28 时才进入移动端布局。
- CSS 移动布局媒体查询改为主触控设备或手机纵向比例触发；PC 端默认锁定 1280px 最小工作台宽度，浏览器逐渐收窄时保持 PC 布局并横向滚动，不再连续压缩各栏。
- 取消平板横屏锁定逻辑，平板横屏也继续显示移动端布局。
- 修复移动端贴纸/拍立得资源列表在折叠图层参数时的滚动容器高度：列表区域固定在控制区到安全区底部之间，由面板自身滚动，避免内容长出视口后无法下滑。

## 验收标准
- 移动端首屏画布占比足够高。
- 功能区不横向滑动。
- 子功能只在母功能选中后出现。
- 空功能区不露出异常色块。
- 清空画布后点击空画布上传下一张照片，移动端仍能打开系统相册/文件选择器。
- 确认腮红后清空画布，再点击空画布上传下一张照片，仍能打开系统相册/文件选择器。
- PC 端普通窄窗口保持 PC 布局，不做连续缩放；达到手机纵向比例窗口后可切换移动端布局。
- 手机、平板任意窗口尺寸保持移动端布局。
- 移动端贴纸列表内容超过一屏时可以在列表区域内纵向滑动，底部贴纸不被安全区或固定面板裁掉。

## 验证结果
- `node --check src/app.js` 通过。
- 已在当前 in-app browser 刷新页面；当前窄高窗口命中手机纵向比例并进入 `force-mobile-layout`，导航仍包含 `导出` 与 `拍立得`。
- 已排查移动端各 tab 固定面板规则，贴纸/拍立得资源列表已补齐内部滚动能力。
