# 资源体积、缓存和部署策略

## 优先级
P1，承接「网页制作方向与 App 封装方案」。

## 任务目的
梳理 Jirai-editor 的静态资源加载、字体体积、贴纸资源、缓存失效和部署策略，降低首屏和移动端网络压力。

## 当前观察
- `assets` 约 49MB。
- `assets/fonts` 约 47MB，是主要体积风险。
- 贴纸资源约 1.6MB，整体可控。
- 当前是静态页面，无构建产物 hash；代码内已有部分字体版本参数。

## 范围
- 区分首屏必需资源、交互后按需资源、可删除或可子集化资源。
- 字体加载策略：移动端子集、按需加载、预览字体延迟加载。
- 贴纸和图片资源缓存策略。
- HTML、JS、CSS、字体、图片的缓存 header 和版本失效策略。
- PWA Service Worker 介入前后的缓存边界。

## 验收标准
- 给出资源清单和体积优先级。
- 给出上线缓存策略建议。
- 明确哪些字体/资源应延迟、子集化或拆包。
- 不改变当前字体审美和贴纸素材选择。
